## 一、目标

在现有日月方位插件中增加“天气”Tab，以当前观察位置为中心，展示从当前时间前 6 小时到未来 5 天的模式天气时间序列，并允许用户在 EC 和 ICON 之间切换预报模型。

界面采用逐时表格，而不是单一云量曲线。表格左侧固定指标名称，右侧按时间排列数据列，并突出当前时间所在位置。

## 三、数据口径

### 1. 数据性质

- [x] 所有数据统一标识为天气模式数据，不描述为历史实况或观测值；
- [x] “过去 6 小时”表示最新模式结果中时间戳早于当前时间的部分；
- [x] 未来时间范围固定裁剪到当前时间后 5 天；
- [x] 根据接口实际返回的时间戳裁剪，不假设任何模型始终提供完整 6 小时；
- [x] 接口不足未来 5 天时只展示实际返回范围，不补造缺失时间点；
- [x] 不补造接口没有返回的时间点；
- [x] 请求使用 1 小时步长；若接口实际返回 3 小时时次，则按真实时间戳展示。

### 2. 数据源

- [x] 使用 `@windy/fetch` 的 `getPointForecastData`；
- [x] 支持 EC 和 ICON 两个模型，分别映射为 `ecmwf` 和 `icon`；
- [x] 默认选择 EC；
- [x] 同一张表中的全部字段必须来自当前选中的同一模型；
- [x] 请求携带当前观察位置的 `lat` 和 `lon`；
- [x] 请求参数使用 `days: 5` 和 `step: 1`；
- [x] 请求 `meteogram: true`，获取露点和各气压层云量；
- [x] 请求 `sounding: true`，获取地表相对湿度；
- [x] 对返回时间序列再次按“当前时间前 6 小时到当前时间后 5 天”裁剪；
- [x] 桌面端打开插件时加载天气数据；移动端首次打开“天气”Tab 时加载；观察位置、模型变化或跨整点时重新请求；
- [x] 位置连续变化时中止旧请求，过期请求不得覆盖新位置数据。

### 3. 字段映射

| 界面字段 | Windy 数据 | 转换规则 |
| --- | --- | --- |
| 日期、时间 | `data.ts` | 按观察位置时区格式化和分组 |
| 天气 | `data.icon`、`data.isDay` | 映射为本地天气图标和无障碍文本 |
| 气温 | `data.temperature` | K 转换为摄氏度并四舍五入 |
| 露点 | `meteogram.dewPoint` | K 转换为摄氏度并四舍五入 |
| 湿度 | `sounding['rh-surface']` | 限制在 0-100%，显示整数百分比 |
| 降水 | `data.precipAmount` | 保持 mm；0 显示 `-` |
| 风速 | `data.wind` | m/s 乘以 3.6，转换为 km/h |
| 风向 | `data.windDir` | 保留角度，绘制旋转箭头 |
| 云量 | `meteogram['cloud-*']` | 按压力层聚合为低云、中云、高云和综合云量 |

### 4. 云层聚合规则

- [x] 低云层使用 `cloud-surface`、`cloud-1000h`、`cloud-950h`、`cloud-925h`、`cloud-900h`、`cloud-850h`；
- [x] 中云层使用 `cloud-800h`、`cloud-700h`、`cloud-600h`、`cloud-500h`；
- [x] 高云层使用 `cloud-400h`、`cloud-300h`、`cloud-250h`、`cloud-200h`、`cloud-150h`；
- [x] 每个云层分组取该时刻组内最大云量，避免直接相加超过 100%；
- [x] 综合云量使用 `1 - (1 - 低云) * (1 - 中云) * (1 - 高云)`；
- [x] 所有输入先归一化到 0-1，结果再转换为 0-100 的整数；
- [x] README 说明综合云量和高中低云为模式压力层聚合结果；
- [x] 缺少整个云层分组数据时显示 `-`，不得用 0 代替未知值。

## 五、界面设计

### 1. 表格结构

- [x] 左侧指标列固定，不随横向时间滚动；
- [x] 右侧数据区独立横向滚动；
- [x] 日期行按观察位置当地日期合并展示；
- [x] 每个时间列固定为 36px，使用与事件 Tab 太阳方位角一致的 10.8px 数据字号，可完整显示三位数；
- [x] 天气图标、数字和风向箭头在列内水平居中；
- [x] 天气图标使用 21px，左侧指标列居中，单位在指标名称下方显示；
- [x] 空值统一显示 `-`；
- [x] 单位只显示在左侧指标名称中，不在每个单元格重复；
- [x] 数值使用等宽数字，避免滚动时视觉跳动。

### 2. 当前时间定位

- [x] 用独立竖线标记当前时间；
- [x] 当前时间位于两个预报点之间时，按时间比例计算竖线位置；
- [x] 初次进入天气 Tab 时自动滚动，使当前时间位于视口左侧约三分之一处；
- [x] 自动定位只执行一次，不得在用户手动滚动后抢回位置；
- [x] 位置刷新或重新加载数据后重新执行一次当前时间定位。
- [x] 切换 EC / ICON 后重新执行一次当前时间定位。

### 3. 滚动交互

- [x] 桌面端支持触控板横向滚动和 `Shift + wheel`；
- [x] 移动端支持单指横向滑动数据区；
- [x] 横向滑动不得带动外层插件面板左右移动；
- [x] 纵向滑动指标列表时仍能滚动天气表格内容；
- [x] 左侧固定列与右侧数据行必须始终垂直对齐；
- [x] 快速连续滑动时不得触发天气重新请求；
- [x] 不使用拖动修改 Windy 主时间轴。

## 九、完成标准

以下条件全部满足后，0.6.0 天气 Tab 才视为完成：

1. 用户可以在桌面端常驻天气区域或移动端“天气 / Weather”Tab 查看当前观察位置的 EC 或 ICON 天气模式数据，并可随时切换模型。

4. 数据列可流畅横向滑动，左侧指标列固定，当前时间位置清晰可见。
5. 位置或模型变化后只显示当前位置和当前模型的数据，不出现旧请求覆盖。
6. 1 小时和 3 小时数据均按真实时间间隔展示，不伪造中间值。
7. 能见度和 AOD 不出现在本期界面、文档或完成声明中。
8. 单元测试、类型检查、代码检查和生产构建全部通过。
9. 桌面端和 iPhone 16 Pro 移动端完成真实 Windy 页面视觉验收。
