# Windy Sun & Moon Path 插件开发计划

- 状态：0.3.0 已实现，待真实 Windy 发布验证
- 计划类型：本地开发清单
- 更新时间：2026-08-16
- 当前边界：代码实现、本地构建和发布包已完成；真实 Windy 登录验证与地图视觉验收需在 0.3.0 上传后完成

## 一、已确认目标

开发一个标准 Windy 插件，在地图上针对用户选择的位置和日期显示：

- 日出方向，或日落方向；
- 事件前 30 分钟方向线；
- 事件时刻方向线；
- 事件后 30 分钟方向线；
- 用户位置、距离用户 200 km 的点、距离用户 400 km 的点。

每条方向线都从用户位置出发，依次经过 200 km 点和 400 km 点：

```text
紫色用户位置 -> 绿色 200 km 点 -> 蓝色 400 km 点
```

## 二、固定图例和交互规则

### 日落图例

- 浅橙色：太阳日落前 30 分钟线；
- 橙色：太阳日落线；
- 暗红色：太阳日落后 30 分钟线；
- 紫色点：用户位置；
- 绿色点：距离用户 200 km 的位置；
- 蓝色点：距离用户 400 km 的位置。

日出沿用同一相对时序规则：事件前 30 分钟、事件时刻、事件后 30 分钟。

### 位置选择

- 插件打开时优先使用 URL 中的经纬度；
- 支持从 Windy 地图右键菜单打开并传入经纬度；
- 插件打开后支持单击地图重新选择位置；
- 观察位置改变后重新计算时间、方位角、200 km 点和 400 km 点；
- 地图平移和缩放不改变观察位置，只改变地图视图。

### 日期和事件

- 默认使用当前日期；
- 支持全部事件，或单独选择日出、日落、月升、月落；
- 支持日期切换；
- 面板显示当地时间、方位角和方向名称；
- 事件不存在时显示明确状态，不绘制无效方向线。

## 三、第一阶段范围

### 包含内容

- 标准 Windy 外部插件结构；
- 客户端计算太阳事件时间和方位角；
- 三条方向线的地理坐标计算；
- 200 km 和 400 km 点位；
- 用户位置紫色点、三组绿色点、三组蓝色点；
- 日出、日落、月升、月落切换；
- 日期和位置切换；
- Windy 地图图层的创建、更新和清理；
- 桌面端和移动端基础布局；
- 单元测试和 Windy 本地加载验证。

### 当前明确不包含

- 根据云层判断是否能够看到日出或晚霞；
- 云底高度、云层边界或地形遮挡计算；
- 卫星云图、ECMWF/GFS/ICON 切换控制；
- 独立 Windy iframe；
- 参考站点的自有后端接口；
- 预报模型数据的路径采样。

### 第二阶段功能

- 月升/月落及前后 30 分钟方向线；
- 实时太阳和月亮方位线；
- 月相、月亮距离和可见照明比例；
- 蓝调时段、日出、月升、日落、蓝调结束、月落时间轴。

## 四、技术方案

### 1. 插件工程

- [x] 基于 Windy 官方插件模板初始化工程；
- [x] 使用 TypeScript + Svelte，保持与官方模板一致；
- [x] 确定插件名称，例如 `windy-plugin-sun-path`；
- [x] 配置 `desktopUI`、`mobileUI`、`addToContextmenu`、`listenToSingleclick`；
- [x] 配置可携带经纬度的 `routerPath`；
- [x] 处理 Windy 移动端 fullscreen 面板关闭时的生命周期：关闭面板保留地图图层和单击监听，下次插件实例接管时统一清理。

### 2. 天文计算模块

- [x] 引入并锁定成熟的太阳位置计算库，优先评估 `SunCalc`；
- [x] 统一日出/日落事件定义，包括大气折射和地平线高度约定；
- [x] 计算观察点当地日期对应的日出或日落时间；
- [x] 计算 `事件时间 - 30 分钟`、`事件时间`、`事件时间 + 30 分钟` 三个时刻的太阳方位角；
- [x] 将方位角统一为以正北为 0°、顺时针增加的角度；
- [x] 将方位角转换为中文方向名称，例如东、东北、西北；
- [x] 处理极昼、极夜或当天不存在日出/日落的情况；
- [x] 对计算结果保留足够精度，界面展示时再格式化。

### 3. 时间和位置模块

- [x] 使用观察点对应的时区生成当地日期时间；
- [x] 处理夏令时，不能直接使用浏览器设备时区代替观察点时区；
- [x] 优先复用 Windy 的 `getTimezoneInfo`；
- [x] 评估是否使用 Windy `getElevation` 作为观察者海拔；
- [x] 将观察点统一保存为 `{ lat, lon }`，避免经纬度顺序混淆；
- [x] 对跨越日期线、接近极区和经度边界的坐标增加测试。

### 4. 方向线和点位模块

- [x] 使用地球表面测地线计算 200 km 终点；
- [x] 使用同一方位角计算 400 km 终点；
- [x] 为三个时刻分别生成 `[用户位置, 200 km 点, 400 km 点]` 三点折线；
- [x] 生成一枚紫色用户位置点；
- [x] 为三条线分别生成绿色 200 km 点；
- [x] 为三条线分别生成蓝色 400 km 点；
- [x] 统一处理经度跨越 `180°/-180°` 的情况；
- [ ] 评估 Windy globe 模式下的折线显示效果。

### 5. Windy 地图集成

- [x] 使用 `@windy/map` 提供的地图实例；
- [x] 使用独立的图层组管理本插件创建的折线和点位；
- [x] 插件打开或位置/日期/事件变化时更新图层；
- [x] 更新时先复用现有对象或成组替换，避免重复叠加；
- [x] 面板关闭时保留地图方向线；下次插件实例接管时移除并重建全部方向线和点位；
- [x] 不默认修改用户当前的 Windy 图层、预报模型和时间轴；
- [ ] 验证地图拖动、缩放、切换底图后方向线仍绑定正确位置。

### 6. 插件面板

- [x] 显示当前纬度、经度和位置状态；
- [x] 显示日期选择器；
- [x] 显示全部、日出、日落、月升、月落切换控件；
- [x] 显示事件时间；
- [x] 显示三条线对应的时间和方位角；
- [x] 显示颜色图例和 200 km/400 km 点位说明；
- [x] 显示实时太阳/月亮方位、月相和月亮距离；
- [x] 显示太阳/月亮轨迹、蓝调、日出、月升、日落、蓝调结束、月落时间轴；
- [x] 桌面端使用 Windy `rhpane` 面板，并设置 520 px 宽度；
- [x] 移动端使用 Windy `small` 面板，保证日期、事件切换和结果信息不被地图遮挡；
- [x] 加载中、计算失败、事件不存在时显示明确状态。

## 五、验证清单

### 计算正确性

- [ ] 使用广州等已知位置核对日出、日落时间；
- [x] 验证三条线的时间顺序严格为前 30 分钟、事件时刻、后 30 分钟；
- [x] 验证每条线的 200 km 点和 400 km 点距离误差在可接受范围内；
- [ ] 验证日出和日落的方位方向符合季节变化；
- [ ] 验证北半球、南半球和赤道附近位置；
- [ ] 验证夏至、冬至和春秋分附近日期；
- [x] 验证极昼、极夜和无有效事件日期。

### Windy 交互

- [ ] 通过插件菜单正常打开；
- [ ] 通过地图右键菜单打开并正确接收经纬度；
- [ ] 单击地图后位置和方向线同步更新；
- [ ] 关闭面板后方向线保留，单击地图可更新位置；
- [ ] 重新打开插件后不残留旧线和旧点；
- [ ] 切换其他 Windy 面板后不产生重复图层；
- [ ] 切换天气图层、预报模型和时间轴后插件不破坏 Windy 原有状态；
- [ ] 桌面端和移动端分别验证布局。

### 视觉验收

- [x] 浅橙色、橙色、暗红色的语义与日落图例一致；
- [x] 紫色点始终为观察位置；
- [x] 每条方向线都有对应的绿色 200 km 点和蓝色 400 km 点；
- [x] 三条线在同一观察点发出，不能出现起点漂移；
- [ ] 点位和线条在常用缩放级别下清晰可见；
- [ ] 线条不会遮挡插件面板中的关键结果信息。

## 七、验收标准

满足以下条件后，第一阶段视为完成：

1. 用户可以在 Windy 中选择位置和日期，并切换日出、日落、月升、月落。
2. 地图上始终只显示当前选择对应的三条方向线。
3. 每条线均从紫色用户位置出发，经过绿色 200 km 点和蓝色 400 km 点。
4. 日落场景中，浅橙色、橙色、暗红色分别准确对应前 30 分钟、事件时刻、后 30 分钟。
5. 面板显示的当地时间和方位角与计算模块结果一致。
6. 面板显示实时太阳和月亮方位，以及当天日月时间轴。
7. 极昼、极夜、无效日期、地图切换和插件关闭等边界场景无错误结果；移动端关闭面板后地图方向线和单击换点仍然可用。
